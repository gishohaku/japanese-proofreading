# 校正チェックリスト

校正のたびに最初に読むファイル。全ルールの要点と重要度をまとめている。判定に迷ったとき、例文が必要なとき、textlint を実行できなかったときだけ、`rules/` の詳細ファイルを読む。

## 重要度

| 重要度 | 意味 | 出し方 |
|---|---|---|
| 誤り | 文法・表記として誤り。意味が通らない、誤読される | 必ず修正案を示す |
| 推奨 | 誤りではないが、読みにくさ・誤解の原因になる | 修正案と理由を一言 |
| 任意 | 表記方針の問題。文書内で統一されていれば可 | 揺れているときだけ指摘 |
| 要確認 | 誤りの可能性があるが、原稿だけでは断定できない（本文とコードの食い違い、章をまたいだ数値の不一致、別概念かもしれない用語）| 何を確かめればよいかを書く。修正案は示せる場合だけ |
| 提案 | 段落・節の読みやすさ（`review.md`）| 校正とは別の節に出す |

- 重要度はこのリストと `rules/` で決める。textlint はすべて error として出すが、その重要度は使わない。
- 誤りか好みか迷ったら、「推奨」か「任意」にする。

## 対象外

次は修正しない（必要なら注意を添えるだけ）。

- コード、コマンド、識別子、ファイル名、URL、エラーメッセージの引用
- 他者の文章の引用、書名、固有名詞・製品名（ただし誤記は GOI-11）
- 用語として定義済みの語、慣用句、会話文・セリフ

## 表記方針の既定値

ユーザーの指定がなく、原稿の多数派もはっきりしないときに使う。決め方の詳細は `rules/toitsu.md`。

- 外来語の語尾の長音は付ける（サーバー）
- 可能の「できる」、補助動詞（〜てください、〜ていただく）、形式名詞（こと、とき）は開く
- 送り仮名は本則
- 句読点とかっこは全角を使う
- 閉じかっこの直前に句点を打たない（「〜です。」と → 「〜です」と）。文末のかっこは、かっこの後に句点を打つ

準拠する基準は、文字・記号が JTF日本語標準スタイルガイド、送り仮名と外来語が内閣告示。文化庁「公用文作成の考え方」（2022年）とは向きが違う点がある（公用文は「及び・又は」と副詞「更に」を漢字で書く、かっこ内で文が終われば句点を打つ、文の長さは50〜60字で読みにくさを意識する）。公用文・官公庁向けの文書だと指定された場合は、そちらに合わせる。

この既定値は `textlint/prh/house.yml` と対応している。原稿の方針が異なる場合、それに反する textlint の指摘は採用しない。

## textlint の指摘の扱い

- textlint の指摘は候補。対象外、本来の意味での使用、原稿の表記方針と食い違うものは採用しない。
- 行番号はルールによってずれることがある。`lint.py` が出す該当文の文字列で照合する。該当文は先頭80字に省略され、リンクの URL は除かれている。全文が必要なら `--full` を付ける。
- `lint.py` は、コード・リンク・かっこ内の補足を除くと100字以下になる長文の指摘を省いている。
- textlint を実行できなかった場合は、「textlint」列が ○・△ のルールも自分で確認する。そのときは該当する `rules/` のファイル（語の一覧がある `okuri.md`、`hiraku.md`、`goi.md`、`moji.md`）を読む。
- `date-weekday-mismatch`（SEIGO-01）は曜日を直す案を出すが、日付のほうが誤っている場合もある。修正案にせず「要確認」で出す。
