# 格助詞・助詞（KAKU, JOSHI）

重要度・対象外・表記方針の既定値は `../checklist.md` を参照。

## 格助詞（てにをは）

### KAKU-01 「は」と「が」の使い分け【推奨】

- 「は」は**主題**（既に話題に出ている情報・旧情報）を示し、文全体にかかる。
- 「が」は**主格**（新しく提示する情報・新情報）を示し、直後の述語にかかる。
- 対比の「は」：「Linux では動く。Windows では動かない」のように、他との対比を含意する。対比の意図がないのに「は」を重ねると、読み手は「では他は？」と感じる。

```
△ 設定ファイルは見つからない場合、デフォルト値が使われる。
○ 設定ファイルが見つからない場合、デフォルト値が使われる。
```
理由：従属節（「〜場合」「〜とき」「〜ので」）の中の主語は原則「が」。「は」は節を越えて文末までかかってしまう。

```
× 私は書いたコードはテストが通らない。
○ 私が書いたコードはテストが通らない。
```
理由：連体修飾節（名詞を修飾する節）の主語は「が」または「の」。「は」は使えない。

### KAKU-02 同じ格助詞の重複【推奨】

一文の中、特に近い位置に同じ助詞が続くと読みにくい。

| 型 | 修正前 | 修正後 |
|---|---|---|
| が・が | 新機能が追加されたことが原因だ | 新機能の追加が原因だ |
| は・は | この関数は引数は2つ取る | この関数は引数を2つ取る |
| を・を（二重ヲ格）| 設定を変更をする | 設定を変更する／設定の変更をする |
| に・に | 午後に会議室に集合する | 午後、会議室に集合する |

二重ヲ格（「〜を〜をする」）は**誤り**として扱う。

### KAKU-03 「の」の連続と曖昧さ【推奨】

- 「の」が3つ以上連続したら指摘する。

```
△ 本書の第3章のサンプルの実行結果
○ 本書第3章にあるサンプルの実行結果
```

- 「AのB」は関係が曖昧になりやすい（所有・作者・宛先・対象など）。誤読のおそれがあれば関係を明示する。

```
△ 部長のレビュー         （部長が行うレビュー？部長が受けるレビュー？）
○ 部長が行ったレビュー
```

- 連体修飾節内では「が」を「の」に置き換えて重複を避けられる（「私が書いたコードが」→「私の書いたコードが」）。

### KAKU-04 「に」と「へ」【任意】

- 「に」：到達点・帰着点そのもの（「サーバーにログインする」「ディレクトリに保存する」）。
- 「へ」：方向（「上位層へ伝播する」「新バージョンへ移行する」）。
- 到達点が明確な技術文書では「に」が自然な場面が多い。

### KAKU-05 「に」と「を」、「に」と「と」【任意】

- 「AにBを〜」「AをBに〜」の取り違えは**誤り**（「APIをリクエストを送る」→「APIにリクエストを送る」）。
- 相互動作の動詞は「と」が双方向、「に」が一方向。「チームと相談する」（互いに）／「上司に相談する」（一方から）。

### KAKU-06 「で」と「が」、「で」と「に」【推奨】

- 「Aでいい」は消極的な選択、「Aがいい」は積極的な選択。推奨を述べる文で「で」を使うと消極的に読まれる。

```
△ 小規模なら SQLite でよい。     （妥協のニュアンス）
○ 小規模なら SQLite が適している。
```

- 存在は「に」、動作の場所は「で」。

```
× 設定ファイルはホームディレクトリである。
○ 設定ファイルはホームディレクトリにある。
○ ホームディレクトリで作業する。
```

### KAKU-07 「から」と「より」【推奨】

起点（時間・場所・出どころ）には「から」、比較には「より」を使う。「より」を起点に使うと比較と紛れる。

```
△ 10時よりメンテナンスを開始する。
○ 10時からメンテナンスを開始する。
○ v2 は v1 より高速だ。
```

### KAKU-08 自動詞・他動詞と格の一致【誤り】

他動詞は「〜を」、自動詞は「〜が」をとる。取り違えると主述がねじれる。

```
× ファイルが保存すると、通知が表示する。
○ ファイルを保存すると、通知が表示される。
○ ファイルが保存されると、通知が表示される。
```

### KAKU-09 可能・願望の対象【任意】

「〜が読める／〜を読める」「〜が見たい／〜を見たい」はどちらも許容される。文書内で揃っていればよい。対象と述語の間に語が多く挟まる場合は「を」のほうが係り受けが明確になる。

## 接続助詞・係助詞・副助詞

### JOSHI-01 接続助詞「が」は逆接に限る【推奨】

「が」には逆接と、単なるつなぎ（前置き・順接）の両方の用法がある。読み手は「が」を見ると逆接を予想するため、論述では逆接だけに使う。

```
△ 前章で環境を構築したが、本章ではアプリを作る。
○ 前章で環境を構築した。本章ではアプリを作る。
○ 前章で環境を構築したので、本章ではアプリを作る。
```

前置きの「が」（「質問ですが、〜」）も論述文では避ける。

一文の中で逆接の「が」を2回以上使ったら必ず指摘する（textlint：`no-doubled-conjunctive-particle-ga`）。

```
× 処理は速いが、メモリを使うが、許容範囲だ。
○ 処理は速い。メモリは多く使うが、許容範囲だ。
```

### JOSHI-02 理由を表す「ので」「から」「ため」【任意】

- 「から」は話し手の主観的な判断・理由、「ので」は客観的な因果関係に向く。
- 技術文書・論述では「ため」「ので」が無難。「〜から」は話し言葉寄り。
- 「〜ため」は目的（〜するために）と理由（〜したため）の両方に使えるので、近くに並べない。

### JOSHI-03 条件「と」「ば」「たら」「なら」【推奨】

| 形 | 主な用法 | 例 |
|---|---|---|
| と | 必ず起きる結果・手順の帰結 | ボタンを押すと、ダイアログが開く |
| ば | 一般的な条件 | 引数を省略すれば、既定値が使われる |
| たら | 前件の完了後に後件が起こる | ビルドが終わったら、テストを実行する |
| なら | 相手の発言・前提を受ける | Docker を使うなら、次の設定が必要だ |

「と」の後件に命令・依頼・意志は来ない（× ボタンを押すと、確認してください → ○ ボタンを押したら、確認してください）。これは**誤り**として扱う。

### JOSHI-04 「〜たり」は対にする【誤り】

「〜たり」は並列する要素すべてに付け、「〜たりする」で受ける。

```
× ログを確認したり、設定を見直すとよい。
○ ログを確認したり、設定を見直したりするとよい。
```

### JOSHI-05 係助詞「も」の並列【推奨】

並列の意味で「も」を使うときは、対になる要素を省かない。省くと読み手は「ほかに何が？」と迷う。

```
△ このツールは Mac も対応している。
○ このツールは Windows も Mac も対応している。
○ このツールは Mac にも対応している。   （「〜にも」で追加を示す）
```

ただし「も」は追加（「〜も必要だ」）、強調（「1秒もかからない」）、類推にも使う。前の文に対になる要素が出ている場合や、これらの用法の場合は指摘しない。

### JOSHI-06 連用中止・「〜て」の連続【推奨】

「〜し、〜し、〜して、〜し」のように連用形や「て」で節を3つ以上つなげた文は、一文一義（BUN-06）に従って分割を提案する。

### JOSHI-07 副助詞「など」「とか」「なんか」【推奨】

- 「とか」「なんか」は話し言葉。書き言葉では「や」「など」に置き換える。
- 「など」を一文に複数回使わない。「〜や〜など」は可。
- 例示が網羅的なら「など」は不要。ぼかす意図がないのに付けると曖昧になる。

### JOSHI-08 逆接の話し言葉【推奨】

「けど」「けれど」「のに」「でも（文頭）」は話し言葉。書き言葉では「が」「しかし」「ところが」などに置き換える。

### JOSHI-09 同じ接続詞の連続【推奨】

連続する文の文頭に同じ接続詞を使わない（textlint：`no-doubled-conjunction`）。

```
△ しかし、設定は正しい。しかし、エラーが出る。
○ 設定は正しい。それでも、エラーが出る。
```

「また」「さらに」「そして」が続く場合も、箇条書きにするか接続詞を減らす。

### JOSHI-10 同じ語の連続【誤り】

「するする」「ののの」など同じ語が連続していたら、入力ミスとして指摘する（textlint：`ja-no-successive-word`）。
