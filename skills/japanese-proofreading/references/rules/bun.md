# 文の構造（BUN）

重要度・対象外・表記方針の既定値は `../checklist.md` を参照。

### BUN-01 語順の原則【推奨】

修飾語が複数あるときは、次の原則で並べる。

1. 長い修飾語を先に、短い修飾語を後に置く。
2. 大きな状況（理由・前提）から小さな状況へ。
3. 重要な情報を先に置く。
4. 時間を表す語は、場所を表す語より前に置く。

```
△ 本番環境で、昨夜23時ごろ、ディスク容量の不足が原因で、APIが停止した。
○ ディスク容量の不足が原因で、昨夜23時ごろ、本番環境のAPIが停止した。
```

### BUN-02 修飾語と被修飾語を近づける【推奨】

修飾語と被修飾語の間に別の語が挟まると、係り先が曖昧になる。

```
△ 大きなサーバーのログファイル     （大きいのはサーバー？ログファイル？）
○ サーバーの大きなログファイル
```

```
△ 素早く入力した値を検証する     （素早いのは入力？検証？）
○ 入力した値を素早く検証する
```

### BUN-03 主語と述語を対応させる（主述のねじれ）【誤り】

主語と述語だけを抜き出して文が成り立つか確認する。

```
× 本章の目的は、テストの書き方を学ぶ。
○ 本章の目的は、テストの書き方を学ぶことだ。
○ 本章では、テストの書き方を学ぶ。
```

```
× このエラーの原因は、メモリが不足したからです。
○ このエラーの原因は、メモリ不足です。
○ このエラーは、メモリが不足したために起きました。
```

主語・述語の省略によるねじれにも注意する。

```
× 設定を変更すると、再起動が必要になり、反映される。
○ 設定を変更した場合は再起動が必要だ。再起動すると変更が反映される。
```

### BUN-04 並列の形を揃える【推奨】

並列する要素は品詞・形を揃える。

```
× このライブラリは高速で、メモリ消費も少なく、導入の簡単さが特長だ。
○ このライブラリは高速で、メモリ消費が少なく、導入が簡単だ。
```

```
× ログの確認や、設定を見直してください。   （名詞句と動詞句が並んでいる）
○ ログを確認したり、設定を見直したりしてください。
○ ログの確認や設定の見直しをしてください。
```

### BUN-05 能動態と受動態【推奨】

- 一文の中で能動と受動が混ざると主述がねじれる。視点（主語）を統一する。
- 書き手自身の行為を受動態で書かない（「〜と考えられる」は推量の慣用として許容）。
- 「〜される」が続く文は、動作主を主語にした能動態に書き換えられないか検討する。

```
△ この関数は多くのプロジェクトが使っている。
○ この関数は多くのプロジェクトで使われている。
○ 多くのプロジェクトがこの関数を使っている。
```

### BUN-06 一文一義・文の長さ【推奨】

- 一文で述べることは1つにする。
- 目安：一文 60〜80 字以内。100 字を超えたら分割を提案する。
- 読点が4つ以上ある文は分割を検討する。
- 手順は1手順1文にする。

### BUN-07 読点の打ち方【推奨】

読点は係り受けを明確にするために打つ。次の位置が基本。

- 長い主語・主題の後（「この章で紹介するすべてのサンプルコードは、」）
- 文頭の接続詞・副詞の後（「しかし、」「まず、」）
- 条件・理由を表す節の後（「〜場合、」「〜ため、」）
- 並列する語句の間
- 係り先を明示したい箇所

```
△ 先輩はエラーを出しながら動かしている後輩を手伝った。
○ 先輩は、エラーを出しながら動かしている後輩を手伝った。   （エラーを出しているのは後輩）
○ 先輩はエラーを出しながら、動かしている後輩を手伝った。   （エラーを出しているのは先輩）
```

### BUN-08 否定表現・二重否定【推奨】

- 肯定で言える内容は肯定で書く（「遅くない」→「速い」）。
- 二重否定は肯定に直す。

```
△ 権限がなければ、実行できないわけではない。
○ 権限がなくても実行できる。
```

- 「〜ない場合は〜ない」のように否定が続くと読み違えやすい。条件を肯定側から書けないか検討する。

### BUN-09 文末表現の単調さ【任意】

同じ文末（「〜です。」「〜です。」「〜です。」）が3文以上続く場合に、単調さを指摘する。敬体と常体の混在は文書全体の集計が必要なので、TOITSU-03 で扱う。

### BUN-10 指示語【推奨】

- 「これ」「その」「上記」などが指す内容が直前の1文にない場合、具体的な語に置き換える。
- 改ページや図表を挟んだ後の指示語は特に置き換える（「この結果から」→「表3-2の結果から」）。

### BUN-11 一人称の削除【任意】

論述で「私は〜と考える」の「私は」は省ける場合が多い。主張を明確にしたいときは削る。ただし個人の経験を述べるエッセイ調の文章では残してよい。
