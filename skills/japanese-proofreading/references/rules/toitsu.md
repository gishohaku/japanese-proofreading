# 文書全体の統一（TOITSU）

重要度・対象外・表記方針の既定値は `../checklist.md` を参照。

## 概要

1文ずつ見ても誤りではないが、文書全体で見ると揺れているものを扱う。判定には文書全体（書籍なら全章）を通した集計が必要なので、`scripts/consistency.py` で集計してから判断する。

## 判定の手順

1. `consistency.py` で、文末・表記・文体の要素ごとに件数を集計する。
2. ユーザーが方針を指定していれば、それを採用する。
3. 指定がなければ、多数派を方針として採用する。ただし、多数派がルール集の誤り（例：「出来る」が多数派）であれば、ルール集を優先する。
4. 拮抗している場合（多数派が全体の7割未満が目安）は、方針を決めない。その揺れは指摘にせず、結果の「方針の確認」に件数と既定値を添えて書き、どちらに統一するかを書き手に委ねる。作業は止めずに進める。
5. 方針と異なる箇所を、語ごと・要素ごとに1件にまとめて指摘する。同じ揺れを箇所ごとに何件も出さない。

重要度は、固有名詞の誤記（GOI-11）と、本文中の文末の混在（TOITSU-03）は【誤り】、それ以外は【任意】または【推奨】とする。

## ルール

### TOITSU-01 同じ語の表記ゆれ【任意】

同じ語が複数の表記で書かれているもの。どの表記を基準にするかは GOI-01 を参照。

| 種類 | 例 |
|---|---|
| 外来語の長音 | サーバー／サーバ、ライブラリー／ライブラリ |
| 外来語の表記 | インターフェース／インタフェース、ウェブ／ウエブ |
| 英字とカタカナ | Web／ウェブ、Eメール／メール |
| 英字の大文字・小文字・記号 | GitHub／Github、JavaScript／Javascript、Node.js／NodeJS |
| 漢字とかな | 事／こと、出来る／できる、全て／すべて |
| 送り仮名 | 行う／行なう、申し込み／申込み、読み込み／読込み |
| 専門用語の表記 | 引数／引き数、戻り値／戻値 |
| 数字 | 1つ／一つ、1か月／1ヶ月 |

固有名詞・製品名の表記が揺れている場合は、多数派ではなく公式表記に合わせ、【誤り】とする（GOI-11）。

数字は、助数詞ごとに算用数字と漢数字の件数を比べる（「一つ」が多数派でも「3か所」が紛れていることがある）。長音は、語ごとの揺れ（サーバー／サーバ）だけでなく、長音を付ける語と省く語が混在していないか（ポインター と コンパイラ）も見る。後者は慣用として使い分けている場合があるので、指摘ではなく方針の確認として尋ねる。

### TOITSU-02 同じ対象を別の語で呼んでいる【推奨】

表記ではなく語そのものが違うが、同じ対象を指しているもの。読み手は別のものだと受け取るおそれがある（TW-C02）。

```
△ 第2章では「利用者」、第3章では「ユーザー」、第4章では「エンドユーザー」と呼んでいる（同じ人を指している）。
→ どれか1つに統一する。区別しているなら、初出で違いを定義する。
```

技術用語では、似ていても別の概念であることが多い（関数とメソッド、エラーと例外、引数と仮引数、ライブラリとフレームワーク）。文脈から同じものを指していると判断できる場合だけ指摘し、迷う場合は「要確認」とする。

### TOITSU-03 文末（敬体・常体）の統一【誤り】

本文の文末は、敬体（です・ます）か常体（だ・である）のどちらかに統一する。

見落としやすい混在：

- 敬体の文章に、常体の文末が紛れる：「〜だ。」「〜である。」のほか、「〜ない。」「〜した。」「〜できる。」のような動詞・形容詞の終止形（敬体なら「〜ません。」「〜しました。」「〜できます。」）
- 常体の文章に、敬体の文末が紛れる：「〜です。」「〜ます。」「〜ください。」（常体なら「〜してほしい。」「〜すること。」）
- 「〜でしょう」「〜ましょう」と「〜だろう」「〜しよう」の混在

例外（指摘しない）：

- 箇条書き、表、図表のキャプション。ただし、1つの箇条書きの中では揃える（TOITSU-04）
- 引用、会話文、セリフ、コード内のコメント
- まえがき・あとがき・コラムなど、節全体で意図的に文体を変えている場合（節の中では統一されていること）
- 体言止め（ただし、本文で多用している場合は【任意】で指摘する）

### TOITSU-04 箇条書きの文末の統一【任意】

1つの箇条書きの中で、項目の形を揃える。

- 体言止め（「設定の変更」）と文（「設定を変更する。」）を混ぜない
- 文にする場合、句点を付けるか付けないかを揃える
- 文にする場合、本文の文体（敬体・常体）に合わせるか、箇条書きはすべて常体にするかを文書内で揃える

### TOITSU-05 一人称・読者の呼び方の統一【推奨】

- 一人称：「私」「僕」「筆者」「著者」「我々」「私たち」を混在させない。ただし、読者と書き手を含む「私たち」と、書き手だけを指す「筆者」を使い分けている場合は除く。
- 読者の呼び方：「あなた」「読者」「皆さん」「みなさん」を混在させない。
- まえがき・あとがきで本文と異なる呼び方をするのは可。

### TOITSU-06 行動の促し方の統一【任意】

手順や推奨の書き方を揃える。

| 形 | 印象 | 向いている文書 |
|---|---|---|
| 〜してください | 指示 | マニュアル、手順書 |
| 〜しましょう | 誘い | 入門書、チュートリアル |
| 〜します | 説明（書き手も一緒に行う）| ハンズオン |
| 〜する／〜すること | 規則 | 常体の文書、規約 |

1つの手順の中で混在させない。節ごとに役割が違う場合（解説は「〜しましょう」、手順は「〜してください」）は可。

### TOITSU-07 敬語の程度の統一【推奨】

「〜します」と「〜いたします」、「〜です」と「〜でございます」、「ご確認ください」と「確認してください」など、丁寧さの程度を文書内で揃える。過剰な敬語は GOI-07 で扱う。

### TOITSU-08 記号・体裁の統一【任意】

MOJI 系のルールのうち、方針が複数あり得るものを文書内で揃える。

- 読点・句点：「、。」か「，．」か
- かっこ：全角「（）」か半角「()」か（和文中）
- 和文と英数字の間のスペースの有無（`consistency.py` は英字だけを数える。「3点」「2026年」のような数字は、スペースを入れる方針でも詰めて書くことが多いため）
- 強調の方法：「」、『』、太字のどれで語を強調・引用するか
- 用語の初出の示し方：太字、かぎかっこ、ルビ
- 単位と数値の間のスペース（10 MB／10MB）、単位の表記（KB／kB／KiB）
- 桁区切り（1,000／1000）

### TOITSU-09 見出しの表現の統一【任意】

同じ階層の見出しで、表現の形を揃える（PW-08）。

```
△ 3.1 インストール ／ 3.2 設定する ／ 3.3 動作確認をしよう
○ 3.1 インストール ／ 3.2 設定 ／ 3.3 動作確認
○ 3.1 インストールする ／ 3.2 設定する ／ 3.3 動作を確認する
```

### TOITSU-10 英字表記とカタカナ表記の使い分け【任意】

技術用語を英字のまま書くか、カタカナにするか、訳語にするかを文書内で揃える（callback／コールバック／呼び出し関数、request／リクエスト）。

- コード中の識別子として言及する場合は英字（`callback` 引数）、概念として言及する場合はカタカナ、のように使い分けているなら揺れではない。
- 英字の語と和文の接続（「Docker イメージ」「Dockerのイメージ」「Docker image」）も揃える。
